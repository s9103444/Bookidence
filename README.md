## 一、這個專案到底是什麼

三個關鍵字，先建立畫面：

| 名詞 | 白話解釋 |
| --- | --- |
| **Vite** | 幫你把 `.vue` 檔案即時轉成瀏覽器看得懂的東西，並開一個本機網頁伺服器讓你邊改邊看結果 |
| **Vue Router** | 負責「網址跟畫面的對應表」。使用者打 `/search`，它就去找該顯示哪個元件 |
| **SCSS** | 加強版 CSS，可以定義變數（像顏色）、可以把樣式片段包成 mixin 重複套用 |

這個專案用**同一個 Vue 專案**做前台跟後台，靠**網址路徑**分區：

- `/` 開頭 → 前台（一般會員看的畫面）
- `/admin` 開頭 → 後台（管理員看的畫面）

兩邊共用同一份 `npm install`、同一個開發伺服器，但畫面外框（Layout）完全不同。

## 二、如何啟動（第一次照著做一次就會了）

1. 用 VS Code 開啟這個資料夾（`檔案 → 開啟資料夾`，選到 `bookidence-frontend` 這一層）
2. 按 `Ctrl + \`` 打開終端機
3. 第一次，或是 `package.json` 有更新時，執行：
   ```
   npm install
   ```
4. 每次要開發，執行：
   ```
   npm run dev
   ```
5. 終端機會印出一個網址（通常是 `http://localhost:5173/`），瀏覽器打開它
6. 網址加上 `/admin` 可以看後台
7. 不用了，回終端機按 `Ctrl + C` 關閉伺服器

**常見卡住點：**
- 打 `npm run dev` 沒反應或報錯 → 通常是忘記先 `npm install`，或是不小心在錯誤的資料夾層級開終端機（確認終端機路徑最後一段是 `bookidence-frontend`）
- 畫面全白、Console 一堆紅字 → 通常是某個 `.vue` 檔案裡的路徑寫錯或語法錯，把錯誤訊息複製貼給我，我可以直接幫你定位問題

## 三、資料夾結構與「為什麼這樣分」

```
src/
├─ assets/scss/
│  ├─ abstracts/
│  │  ├─ _variables.scss   ← 顏色、間距等數字，改這裡全站跟著變
│  │  └─ _mixins.scss      ← 可重複套用的樣式邏輯（例如響應式斷點）
│  ├─ base/
│  │  ├─ _reset.scss       ← 抹平瀏覽器預設樣式差異
│  │  └─ _typography.scss  ← 全站字型、顏色
│  └─ all.scss             ← 總入口，main.js 只 import 這一個檔
│
├─ layouts/
│  ├─ FrontLayout.vue      ← 前台外框（頂部導覽列）
│  └─ AdminLayout.vue      ← 後台外框（側邊欄）
│
├─ views/
│  ├─ front/                ← 前台頁面，一個檔案 = 一個頁面
│  └─ admin/                ← 後台頁面
│
├─ router/
│  ├─ front.js              ← 前台的「網址對照表」
│  ├─ admin.js               ← 後台的「網址對照表」
│  └─ index.js                ← 把上面兩份合併起來
│
├─ App.vue                  ← 幾乎是空的，只負責顯示 <router-view />
└─ main.js                  ← 程式的起點，掛上 router 跟全域 SCSS
```

**為什麼 `views` 要拆 `front` / `admin` 兩個資料夾？**
因為你負責的會員系統橫跨前後台——前台會員可以改自己的暱稱，後台管理員可以管理所有會員。這兩個畫面雖然功能相關，但長相完全不同，拆開放才不會越找越亂。

**為什麼變數 (`_variables.scss`) 開頭要加底線？**
底線開頭的 SCSS 檔案叫 partial，代表「這只是一個片段，不要單獨編譯成一個 CSS 檔」，要被別的檔案 `@use` 進去才會真正生效。這是 SCSS 的命名慣例，不是我們自己發明的規則。

## 四、路由是怎麼運作的（這是最重要的觀念）

打開 `src/router/front.js`，你會看到長這樣的結構：

```js
{
  path: 'search',                              // 網址是 /search
  name: 'search',                              // 這個路由的代號，程式裡可以用代號跳轉
  component: () => import('../views/front/SearchView.vue'),  // 對應要顯示的畫面
}
```

白話翻譯：**使用者網址打到 `/search`，就把 `SearchView.vue` 這個檔案的內容塞進畫面裡。**

`() => import(...)` 這個寫法看起來很怪，但你只要記住一個規則：**複製貼上就好，不用改寫法，只要換裡面的路徑跟檔名**。它的作用是「先不要載入這個頁面，等使用者真的點到這裡才去下載」，這樣使用者第一次進網站不用一次下載全部 100 多個頁面。

`App.vue` 裡只有一行 `<router-view />`，代表「這裡是一個洞，router 決定塞什麼元件進來」。而 `FrontLayout.vue` 和 `AdminLayout.vue` 裡也各自有一個 `<router-view />`——這是**巢狀結構**：外層決定用前台外框還是後台外框，內層才是實際頁面內容。

## 五、動手練習：新增一個「我的通知」頁面

這是你負責的 F1 通知中心，用這個當練習題，做完你就會完全理解流程。

**第一步：建立頁面檔案**
在 `src/views/front/` 建立 `NotificationView.vue`：
```vue
<template>
  <div>
    <h1>我的通知</h1>
    <p>這裡之後會放通知列表。</p>
  </div>
</template>
```

**第二步：加進路由表**
打開 `src/router/front.js`，在 `children` 陣列裡加一筆（跟著既有的格式，用逗號隔開）：
```js
{
  path: 'notifications',
  name: 'notifications',
  component: () => import('../views/front/NotificationView.vue'),
},
```

**第三步：存檔，回瀏覽器**
`npm run dev` 還開著的話不用重啟，存檔後瀏覽器會自動更新。網址列打 `http://localhost:5173/notifications`，應該就能看到你剛剛寫的內容。

如果卡在任何一步，把錯誤訊息或現在的畫面截圖給我，我會直接告訴你哪裡錯、怎麼改。

## 六、Git 分支工作流程（團隊協作）

**核心規則：不要直接在 `dev` 上面改東西。** 每個人從 `dev` 拉出自己的分支開發，做完再合併回去。這樣就算改壞了，也不會直接影響組員共用的進度。

### 分支結構

```
main                      ← 最穩定、可展示的版本，平常不會有人直接推東西上去
└─ dev                    ← 團隊共用的開發進度，大家的分支都從這裡拉出去、也合併回這裡
   ├─ feature/f1-account      ← 尤尤負責，帳號與會員系統
   ├─ feature/f2-xxx          ← 其他組員依此類推
   └─ feature/f3-xxx
```

命名規則：`feature/` 開頭代表這是功能開發分支，後面接負責的模組代號。SourceTree 看到分支名稱有 `/`，會自動把同樣開頭的分支收進同一層資料夾方便管理，不用另外設定。

### 建立自己的分支（第一次做，之後不用重複）

1. 確認目前站在 `dev` 上（左側 BRANCHES 清單裡 `dev` 是目前選取狀態，且是最新進度）
2. 上方選單 `Actions → Branch`，或在 `dev` 上按右鍵選 `Branch`
3. 輸入分支名稱，例如 `feature/f1-account`
4. 確認來源分支是 `dev`
5. 點 `Create Branch`，SourceTree 會自動切換過去

### 日常開發流程

1. 確認自己站在 `feature/f1-account`（不是 `dev` 也不是 `main`）
2. 改程式碼、存檔
3. SourceTree 左側 `File Status` → 勾選要提交的檔案（或按「全部暫存」）
4. 下方留言框寫清楚這次做了什麼，例如：`新增使用者設定頁面路由`
5. 點 `Commit`
6. 點 `Push`，把自己分支的進度推上 GitHub（第一次推會問要不要建立對應的遠端分支，選是）

### 想把自己的進度合併回 dev

**不要**在 SourceTree 裡直接對 `dev` 做 Merge。改成到 GitHub 網頁上開一個 **Pull Request**（從 `feature/f1-account` 合併到 `dev`），讓組員可以看過內容再合併。這樣比較安全，也讓大家知道 `dev` 多了什麼。

### 遇到「兩份東西要合併」的情況（例如組員檔案沒接進專案）

先確認對方的資料夾裡有沒有 `package.json`：
- **有**：代表對方是照同一個 Vite 專案架構延伸做的，直接比對 `src` 底下同名資料夾，合併相對單純。
- **沒有**：代表對方只是丟出零散檔案（例如純 `.scss`），還沒接進任何專案。這時候要以自己現有的 Vite 專案為主體，把對方的檔案內容「嫁接」進對應資料夾，而不是兩邊互相覆蓋。合併完一定要先 `npm install` + `npm run dev` 確認能正常跑，再 Commit、Push。

## 七、名詞小抄

| 詞 | 意思 |
| --- | --- |
| component（元件） | 一個 `.vue` 檔案，可以想成一塊可重複使用的畫面積木 |
| props | 父層元件傳資料給子層元件的方式（還沒用到，之後串資料時會遇到） |
| layout | 固定不變的外框（導覽列、側邊欄），裡面內容會隨頁面替換 |
| route / 路由 | 網址跟畫面的對應規則 |
| lazy loading | 「用到才載入」，不用時不下載，加快網站速度 |
